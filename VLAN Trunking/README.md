# VLAN Trunking – Cisco Packet Tracer

## Overview

This project extends the earlier single-switch VLAN lab by demonstrating **VLAN trunking** between two Cisco 2960 switches using **802.1Q encapsulation**.

Two switches were connected via a trunk link, allowing **VLAN 10 (EMPLOYEES)** and **VLAN 20 (GUESTS)** to span across both switches. Devices belonging to the same VLAN — even when physically connected to different switches — were able to communicate directly, while a trunk link carried the tagged traffic for both VLANs over a single physical connection.

This hands-on exercise builds on the earlier **VLAN Configuration and Segmentation** lab and continues the self-learning journey in computer networking and cybersecurity.

---

## Objectives

- Understand the purpose of VLAN trunking between multiple switches.
- Configure an 802.1Q trunk link between two switches.
- Understand trunk parameters: allowed VLANs, native VLAN, and encapsulation type.
- Verify trunk status using `show interfaces trunk`.
- Verify VLAN membership across switches using `show vlan brief`.
- Test and confirm same-VLAN connectivity across two different switches.
- Analyze ARP broadcast PDU behavior for cross-switch, same-VLAN traffic.
- Understand how a trunk link allows multiple VLANs to share a single physical connection.

## Network Topology

Two switches (Switch0, Switch1) were connected via a trunk link. Each switch hosts one device from VLAN 10 and one from VLAN 20.

| Laptop3 | 192.168.10.20 | Switch1 | 10 (EMPLOYEES) |

## VLAN Configuration Verification

VLAN membership was verified on the switch using `show vlan brief`, confirming both VLANs were active with their respective access ports.

![VLAN Trunking Configuration](VLAN%20Trunking%20Configuration.png)

|---|---|---|---|
| 1 | default | active | Fa0/5–Fa0/24, Gig0/1–Gig0/2 *(unused)* |
| 10 | EMPLOYEES | active | Fa0/1, Fa0/2 |
| 20 | GUESTS | active | Fa0/3, Fa0/4 |

## Trunk Link Verification

The inter-switch link was verified as an active 802.1Q trunk carrying both VLANs.

![Trunk Verification](Trunk%20Verification.png)

| Parameter | Value |
|---|---|
| Port | Fa0/1 |
| Mode | on (trunking) |
| Encapsulation | 802.1Q |
| Native VLAN | 1 |
| VLANs allowed on trunk | 1–1005 |
| VLANs active in management domain | 1, 10, 20 |

## VLAN 10 – Cross-Switch Connectivity

PC1 (`192.168.10.10`, Switch0, VLAN 10) successfully pinged Laptop3 (`192.168.10.20`, Switch1, VLAN 10) across the trunk link. All 4 packets were delivered with **0% loss**, TTL = 128, confirming that same-VLAN devices communicate seamlessly even across separate switches.

![VLAN 10 across switch connectivity](VLAN%2010%20across%20switch%20connectivity.png)

The ARP broadcast generated by this request was traced using Simulation Mode, showing the frame arriving at Laptop3 with source PC1 and destination Broadcast.

![VLAN 10 across switch connectivity PDU Details](VLAN%2010%20across%20switch%20connectivity%20PDU%20Details.png)

## VLAN 20 – Cross-Switch Connectivity

PC2 (`192.168.20.10`, Switch0, VLAN 20) successfully pinged Laptop4 (`192.168.20.20`, Switch1, VLAN 20) across the same trunk link. All 4 packets were delivered with **0% loss**, TTL = 128 — confirming VLAN 20 traffic was also correctly tagged and forwarded over the trunk to reach its VLAN 20 peer on the other switch.

![VLAN 20 across switch connectivity](VLAN%2020%20across%20switch%20connectivity.png)

The corresponding ARP broadcast PDU was captured at Laptop4, showing source PC2 and destination Broadcast.

![VLAN 20 across switch connectivity PDU Details](VLAN%2020%20across%20switch%20connectivity%20PDU%20Details.png)

## Key Learning Outcomes

- A trunk link uses 802.1Q tagging to carry traffic for multiple VLANs over a single physical connection between switches.
- Devices in the same VLAN can communicate across different switches as long as a properly configured trunk connects them.
- `show interfaces trunk` verifies trunk status, encapsulation, native VLAN, and allowed VLAN list.
- `show vlan brief` confirms VLAN creation and access port assignment on each switch.
- VLAN identity — not physical switch location — determines which devices can communicate directly at Layer 2.
